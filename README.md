# GRILLYAZH — официальный сайт

Одностраничный сайт артиста со звуком: хиты играют прямо на сайте, предстоящий релиз, концерты, фото,
заявка для организаторов и контакты.

## Что внутри

Тёмная эстетика: огромный Oswald капсом и Inter для текста,
подписи мелким капсом с разрядкой, тонкие линии, плёночное зерно.

- **Вход со звуком:** после загрузки — крупная кнопка «Включить звук»
  (браузеры разрешают звук только после клика). Можно войти и без звука, включить его позже в плеере.
- **Первый экран:** фото со сцены на WebGL. За курсором (или пальцем) остаётся «горячий след»,
  а под бас картинка вспыхивает и слегка плывёт. Логотип растянут ровно на всю ширину экрана.
- **Предстоящий релиз:** при прокрутке обложка сгорает от краёв (WebGL), из-под пепла появляются
  дата, обратный отсчёт и кнопка пресейва. После даты выхода блок сам становится «Новый релиз · Слушать».
- **Хиты:** экран делится на три части; на каждой свой трек, фото и обложка. Музыка плавно
  переключается вместе с прокруткой, фон и заголовок качаются в такт.
- **Плеер** внизу: обложка-пластинка, эквалайзер по настоящему звуку, пауза, ссылка «Полностью» на Яндекс.
- **Манифест:** строки с фото прямо внутри текста едут навстречу друг другу.
- **Музыка:** список релизов; при наведении справа меняется обложка (на телефоне — при прокрутке).
- **Тур:** даты сами делятся на ближайшие и прошедшие. Если ближайших нет — бегущая строка «Новые даты скоро»
  и кнопка Telegram.
- **Кадры:** три колонки фото едут с разной скоростью, фото раскрываются шторкой, по клику — просмотр.
- **Букинг:** форма открывает Telegram менеджера и копирует текст заявки.
- **Анимации:** GSAP и ScrollTrigger, плавная прокрутка Lenis, свои шейдеры на чистом WebGL, Web Audio для анализа звука.
- При `prefers-reduced-motion` сложные анимации отключаются, сайт остаётся полностью рабочим.

## Как обновлять контент

Весь контент лежит в `src/data.js`:

- `upcoming`: предстоящий релиз (название, дата, обложка, ссылка на пресейв).
- `hits`: три трека, которые играют на сайте, с фото и обложками.
- `releases`: дискография. Чтобы кнопка вела на конкретный релиз, вставьте ссылку в `url`.
- `concerts`: концерты. Дата в формате `2026-04-26T20:00:00+03:00`. Прошедшие концерты сами уходят в архив.
- `gallery`: фото в блоке «Кадры».
- `socials`, `manager`: ссылки и правила для менеджера.

**Яндекс Музыка.** Сборка на GitHub каждые несколько часов запускает `scripts/yandex-sync.mjs`:
скрипт читает страницу артиста (без скачивания музыки) и кладёт в сайт `yandex.json`
с предстоящим релизом, дискографией и обложками. Если Яндекс не ответил, сайт берёт данные из `data.js`.

**Треки.** В `public/audio/` лежат превью припевов (около 40 секунд, mp3 192 кбит/с), вырезанные из полных треков.
Новый трек: вырежьте кусок, например
`ffmpeg -ss 30 -t 42 -i трек.mp3 -af "afade=t=in:d=0.6,afade=t=out:st=38.5:d=3.5" -b:a 192k public/audio/имя.mp3`,
и добавьте запись в `hits`.

**Фото** лежат в `public/photos/` в формате WebP. Обложки «В городе», «Двинулся на тебе» и «Выше градус»
пока вырезаны из видео старого сайта, а обложка предстоящего релиза — со скриншота; их стоит заменить оригиналами
с теми же именами (квадрат от 1500×1500). Перевести JPG в WebP: `cwebp -q 88 photo.jpg -o photo.webp`.

## Запуск

```bash
npm install
npm run dev
```

Сборка: `npm run build` (результат в `dist/`).

## Публикация на GitHub Pages

Workflow `.github/workflows/pages.yml` собирает сайт и выкладывает его при каждом пуше.
Один раз включите Pages: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
